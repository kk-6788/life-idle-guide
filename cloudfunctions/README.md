# 微信云开发：邀请与闲聊

这份公开源码提供 30 人邀请试用、留言、回复、举报与人工审核。邀请码绑定一个微信账号，已激活账号再次进入不重复占名额；暂停成员不释放名额。公开仓库不包含正在使用的邀请码、管理员身份或数据库导出。

## 配置自己的账号

1. 将 `miniprogram/project.config.json` 的占位 AppID `wx0000000000000000` 换为自己的 AppID。
2. 将 `cloudfunctions/idleGuide/core.js` 的身份校验 AppID 换为同一 AppID。若运行测试，也同步修改 `tests/cloud-invite.test.cjs` 的测试 AppID。
3. 将 `miniprogram/config.js` 的 `CLOUD_ENV` 换为自己的微信云开发环境 ID。
4. 在自己的环境创建 `idle_guide` 集合，设置“所有用户不可读写”，或使用 `database.rules.json` 的规则。后台云函数通过 SDK 访问，客户端无法绕过邀请码直接读取。
5. 为列表查询建立四组索引：`kind,status,createdAt,_id`；`kind,parentId,status,createdAt,_id`；`owner,createdAt,_id`；`status,createdAt,_id`。前置字段升序，`createdAt` 与 `_id` 降序。
6. 云函数目录为 `idleGuide/`，使用其中的依赖锁文件安装官方 `wx-server-sdk`，再部署到自己的环境。云函数依赖安装和部署会改变云环境，需由环境所有者自行确认。

## 初始化邀请资格

在仓库根目录运行以下脚本，输出写入被 Git 忽略的私有目录：

```bash
node tools/create-invites.cjs private/first-batch
```

它会生成 30 枚随机邀请码和 `state-首次初始化.json`。未使用的码 90 天到期；已激活成员不因邀请码到期退出。脚本不会打印原始邀请码，也拒绝覆盖已有批次。

初始化文件的 `admins` 默认为空。管理员必须由环境所有者取得该小程序的真实云端 `OPENID`，将其 SHA256 哈希写入 `admins`；不要使用客户端上传的身份，也不要让首位访客自动获得管理员身份。管理员自己也需要兑换邀请码，会占一个名额。

确认集合尚无 `state` 文档，再导入初始化文件。**不要将 seed 重新导入已有环境**，否则会覆盖成员和邀请状态。不要提交或公开邀请码、身份、数据库导出。

## 权限与审核

- 所有业务接口均检查邀请资格，管理接口另行检查管理员身份。
- 留言、昵称和回复先人工审核，审核后展示；用户可删除自己的内容，也可以举报。
- 身份保存 SHA256 哈希，仍属于账号关联数据，需要在隐私说明中如实披露。
- 发言、回复、举报每账号每小时最多 20 次，间隔至少 10 秒；错误邀请码每小时最多尝试 10 次。这些限制不是费用硬上限。
- 列表每页 20 条，不自动轮询；当前未接入自动内容安全接口。

## 验证与发布

```bash
node --test tests/cloud-invite.test.cjs tests/mini-invite.test.cjs
```

本地测试不能替代真实双账号、并发抢码、31 人上限、断网恢复等云端验收。源码包含转盘和昵称输入框调整；真实手机体验仍需自行核对。

云函数部署、开发者预览、体验版、正式发布是不同阶段。普通小程序码能否让访客进入，由该小程序当前发布与访问状态决定，邀请码不能绕过微信平台的限制。
